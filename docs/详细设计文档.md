# 新加坡红酒项目（智能分酒模式）详细设计文档

> 版本: V1.0 | 日期: 2026-09-25 | 框架: Spring Boot 3.2 + MyBatis-Plus 3.5

## 1. 系统总体架构

### 1.1 分层架构

```
┌──────────────────────────────────────────────────────┐
│  客户端层                                              │
│  ├─ Flutter APP (iOS/Android) — 按杯选酒/支付/出酒     │
│  └─ 管理后台 (Ant Design Pro) — 平台/酒吧/酒商三端    │
├──────────────────────────────────────────────────────┤
│  接口层 (Controller)                                   │
│  AuthController / OrderController / PaymentController │
│  DispenseController / AdminController / MenuController│
├──────────────────────────────────────────────────────┤
│  服务层 (Service)                                     │
│  AuthService / OrderService / PaymentService          │
│  DispenseService / ReconcileService / BarOpService    │
├──────────────────────────────────────────────────────┤
│  数据层 (Mapper + Client)                             │
│  MyBatis-Plus Mapper / AllinpayIntlClient / Redis     │
├──────────────────────────────────────────────────────┤
│  存储层                                                │
│  MySQL 8.0 + Redis 7                                  │
└──────────────────────────────────────────────────────┘
```

### 1.2 核心设计决策

| 决策 | 选型 | 理由 |
|------|------|------|
| 双单解耦 | Order + DispenseTicket 独立状态机 | 硬件故障不锁死交易，资金域与机械域物理隔离 |
| 支付架构 | 通联国际CNP页面跳转 | APP不持密钥，卡数据不经商户侧→PCI DSS合规 |
| 资金中立 | asinfo分账指令 | 资金T+1直清酒吧子商户，平台不归集→规避"二清" |
| 并发控制 | Redis分布式锁+原子SQL | 双重防超卖，下单预占+出酒确认 |
| 年龄合规 | 出生日期脱敏输入 | 不存NRIC，配合现场抽查双保险 |

## 2. 核心模块设计

### 2.1 认证模块（AuthService）

**职责**: SMS OTP登录 / Apple/Google三方登录 / 法定年龄校验

| 方法 | 接口 | 逻辑 |
|------|------|------|
| sendSmsCode | POST /auth/sms/send | Twilio Verify API下发6位验证码（不存明文） |
| login | POST /auth/login | 校验验证码→查找/创建用户→签发JWT |
| verifyAge | POST /auth/age-verify | 出生日期→Period计算→满18岁设age_verified=true |

**合规要点**:
- 严禁采集/存储NRIC
- 短信内容使用中性品牌名 `[SGVerify]`，避免酒类字样
- Verify Service SID为账户级配置，开发生产共用

### 2.2 交易订单模块（OrderService）★

**职责**: 下单计价 / 幂等防重 / 容量预占 / 超时关闭

```
createOrder(userId, req, idempotencyKey)
  │
  ├─ 1. 幂等校验（Redis缓存 + 分布式锁 + 双重检查）
  │     cacheKey = wine:idem:order:{idempotencyKey}
  │     lockKey  = idem:{idempotencyKey}
  │
  └─ 2. doCreateOrder
       ├─ 年龄合规校验（age_verified=true）
       ├─ 后端统一计价（查bar_wine_menu获取price）
       │   original_amount = menu.price
       │   discount_amount = 0（一期无促销）
       │   paid_amount = original - discount
       ├─ Redis锁瓶位 + 原子扣减容量（deductCapacity）
       ├─ 创建PENDING订单 + 设置支付超时(payExpireTime)
       └─ 写入幂等缓存（24h TTL）
```

**幂等三重保障**:
1. Redis缓存命中 → 直接返回
2. Redis分布式锁 → 串行化同一key
3. 锁内二次检查 → 防并发穿透

### 2.3 支付模块（PaymentService）★

**职责**: 通联收银台下单 / 异步回调验签 / 原路退款 / 分账

| 方法 | 逻辑 |
|------|------|
| pay(orderNo) | 调AllinpayIntlClient.createOrder(orderNo, cusid, amount, subject)→含asinfo分账指令→订单转PAYING |
| handleNotify(params) | RSA2验签→幂等(PAYING才处理)→金额/币种校验→成功转PAID+生成履约单 / 失败回退PENDING |
| refund(orderNo) | 调AllinpayIntlClient.refund()→订单转REFUNDED→返还预占容量 |
| queryAllinpayAuthStatus(txnId) | 调通联Query API→返回支付状态(三向核对基准) |

**asinfo分账指令格式**: `cusid:01:paid_amount`（01=分账类型，金额单位元）
**3DS规则**: ≥100SGD强制3DS / 新客首单强制3DS（通联收银台自动完成）
**异步通知**: 公钥验签 + 幂等去重 + 定时轮询Query兜底

### 2.4 分酒机履约模块（DispenseService）★

**职责**: 状态查询 / 幂等出酒 / 结果回调 / 取消退款

| 方法 | 逻辑 |
|------|------|
| checkStatus(dispenserId, slotNo) | 查询分酒机就绪状态（含cup_present杯位感应） |
| startDispense(orderNo) | 校验履约单READY→校验cup_present=1→转DISPENSING→下发出酒指令(order_id幂等) |
| handleCallback(params) | 成功→履约单SUCCESS+主订单COMPLETED / 失败→**调paymentService.refund()**全额退款+损耗审计 |
| cancelBeforeDispense(orderNo) | 履约单FAILED→**调paymentService.refund()**原路退款 |

**SLA约束**: 指令响应≤3s / 出酒≤30s / 超时容忍≤45s
**损耗口径**: actual_ml < target-5ml → 全额退款 + 差额入损耗审计

### 2.5 T+1核对模块（ReconcileService）★

**职责**: 每日02:00跑批，三向对齐核对

```
reconcile(date)
  │
  ├─ 查询当日全部订单
  │
  └─ 逐单三向对齐:
       第一向: 本地主订单状态(order.status)
       第二向: 硬件履约单状态(dispense_ticket.status)
       第三向: 通联授权状态(queryAllinpayAuthStatus)
       │
       ├─ 异常D: 通联与本地不一致 → 以通联为准修正
       ├─ 正常: 支付成功+出酒成功 → 归档（检查损耗>5ml→异常C）
       ├─ 异常A: 支付成功但未出酒 → 自动补偿退款
       └─ 异常B: 未支付但出酒成功 → 黄色盗刷告警
```

| 异常 | 条件 | 处理 |
|------|------|------|
| A(漏单) | 支付成功+无出酒记录 | 自动补偿全额退款 |
| B(盗刷) | 未支付+出酒成功 | 最高级别黄色安全告警 |
| C(损耗) | 支付成功+出酒成功+损耗>5ml | 记损耗审计+瓶位标记需校准 |
| D(授权不一致) | 通联与本地状态不符 | 以通联为准修正本地 |

### 2.6 换瓶SOP模块（BarOperationService）

**职责**: 标准换瓶流程 / 容量重置 / 损耗口径

```
changeBottle(req)
  ├─ 查找/创建瓶位
  ├─ 上一瓶残留量处理:
  │   residual ≤ 10ml → 合理物理损耗，自动核销
  │   residual > 10ml → 记录异常损耗审计，提示确认
  ├─ 重置瓶位: wineSkuId/initialCapacity/currentCapacity/batchNo
  └─ 清除need_calibration标记
```

### 2.7 定时任务模块（ScheduledTasks）

| 任务 | Cron | 逻辑 |
|------|------|------|
| dailyReconcile | `0 0 2 * * ?` | T+1三向核对跑批 |
| closeExpiredOrders | `0 * * * * ?` | 扫描PENDING超时订单→关闭+返还容量 |

## 5. 并发与一致性保障

### 5.1 防超卖三重保障

| 层 | 机制 | 实现 |
|----|------|------|
| Redis | 分布式锁 | `wine:lock:slot:{dispenserId}:{slotNo}` 锁定瓶位 |
| DB | 原子SQL | `UPDATE...WHERE current_capacity >= volume` 行锁扣减 |
| 应用 | 事务回滚 | 扣减失败抛异常，@Transactional回滚 |

### 5.2 幂等去重

| 场景 | 幂等键 | 机制 |
|------|--------|------|
| 重复下单 | Idempotency-Key | Redis缓存+锁+双重检查，24h TTL |
| 重复支付回调 | 订单状态 | 非PAYING状态直接返回success |
| 重复出酒 | order_id | 履约单状态校验，DISPENSING/SUCCESS拒绝 |
| 重复退款 | 订单状态 | 非PAID/PAYING状态拒绝 |

## 6. 安全与合规

### 6.1 新加坡PDPC隐私合规

| 要求 | 实现 |
|------|------|
| 严禁采集NRIC | sys_user表无NRIC字段，全流程不采集 |
| 年龄脱敏核验 | 仅存储birth_date，不存证件号/照片 |
| 短信内容合规 | 品牌名 `[SGVerify]`，无酒类字样 |

### 6.2 支付安全

| 要求 | 实现 |
|------|------|
| APP不持密钥 | 通联私钥仅在后端AllinpayIntlClient |
| 异步验签 | RSA2(SHA256withRSA)公钥验签 |
| 金额防篡改 | 后端计价，忽略客户端金额；回调金额校验 |
| 3DS强制 | ≥100SGD/新客首单（通联收银台自动） |
| 资金中立 | asinfo分账，T+1直清酒吧子商户 |

### 6.3 JWT认证

- Header: `Authorization: Bearer {token}`
- 算法: HS256
- 过期: 3600s
- 过滤器: JwtAuthenticationFilter 校验token→查用户→设置SecurityContext
